Gemma3-4B (`google/gemma-3-4b-it`, added to MODEL_NAME_MAP as `gemma-3-4b-instruct`) loads as **multimodal `Gemma3ForConditionalGeneration`** with text layers NESTED at `model.model.language_model.layers` (34 layers, down_proj 2560x10240). Bringing up the attack pipeline needed 6 fixes (all applied):

1. **Nested layer accessor**: added `_decoder_layers(model)` helper (activation_subspace.py + build_model_at_gamma.py) that returns `model.model.layers` OR `model.model.language_model.layers`. Replaced all hardcoded `model.model.layers`.
2. **Wanda metric naming**: metrics keyed `model.language_model.layers.{i}.mlp.down_proj.weight.pt`; loader `_load_keep_and_prune_masks` now tries both `model.layers.*` and `model.language_model.layers.*`. Metrics generated by scratchpad/gen_metrics_gemma3.py (standalone |W|*||X||, 128 wikitext calib).
3. **Tied-weight save**: Gemma3 ties embed_tokens<->lm_head (same tensor); safetensors can't save shared storage AND named_parameters() dedups so the naive untie loop is a no-op. Fix: `model.get_output_embeddings().weight = nn.Parameter(clone)` + set `config.tie_word_embeddings=False` (and text_config) so reload doesn't re-tie. Patched in activation_subspace save + build_model_at_gamma save (with safe_serialization=False fallback).
4. **Processor for vLLM**: vLLM loads Gemma3 as multimodal and needs preprocessor_config.json; save step now also does `AutoProcessor.from_pretrained(repo).save_pretrained(dir)`. Pruned dirs need it copied from checkpoint-last (runner does cp preprocessor_config.json/processor_config.json/chat_template.jinja).
5. **vLLM startup timeout**: multimodal + torch.compile exceeds the 330s startup wait. Fixed in vllm_runner.py: added `--enforce-eager` to vllm_serve_cfg (skips compile, ~30-60s startup) + trials 10->20. CONFIRMED: vLLM serves gemma3-4b, unpruned val jb=0.033.
6. **llmcompressor sequential targets**: Gemma3 `_no_split_modules` lists VISION classes (SiglipTextEmbeddings, SiglipMultiheadAttentionPoolingHead) -> "Could not find targets" error. Fixed in prune/llmcompressor.py prune(): for multimodal wrappers set `model._no_split_modules=[<text decoder layer class>]` + modifier.sequential_targets before oneshot.

**CRITICAL gamma-scale bug (found after first sweep gave flat base-rate noise):** post_norm_aware=TRUE collapses gamma for Gemma3 because its post_feedforward_layernorm weights are GENUINELY LARGE (rms(g)~26-169, mean~24, max~236 — NOT OLMo's ~1). Formula gamma_eff=gamma*s/rms(g) => gamma_eff~0.01 => edit norm ~0.02 => no effect, gamma-invariant results all = base ~4%. FIX: set post_norm_aware=FALSE for Gemma3 and use RAW gamma ~1-2 (edit norms then ~4-5). Calibrated (split band, a0.5, val): g0.5=2.5/22.5, g1=2.5/55, **g1.5=8.3/85 gap+76.7 OR=0% (SWEET SPOT)**, g1.7=15/83, g2=20/92.5. Gemma3 gamma scale is ~1-2, NOT the 5-24 of other models. Over-refusal stays 0% through the knee.

Config: configs/jailbreak/50_1/gemma3-4b.yaml (output_gemma3, post_norm_aware FALSE). Also added gemma-3-4b to requires_causal_mask_replacement list. Prune is SLOW (~15-30min sequential per prune even at 128 calib) -> created wanda_20_g3fast.yaml (128 calib) for sweeps. The 10h sweep: scratchpad/gemma3_sweep.sh (bands split/mid/late x alpha 0.5/0.75 x gamma 5/8/12, val n=300). See [[qwen-benchmark-table]].
